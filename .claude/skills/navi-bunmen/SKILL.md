# 診断ナビの文面を直す

対象は `pc-shindan-navi/`。画面の文字はほぼすべて `app.js` の先頭にまとまっている。
直したら **必ず `sw.js` の `CACHE` の番号を1つ上げる**（上げないとホーム画面に追加したiPadに新しい版が届かない）。

## 1. どこを直すか

| 直したいもの | 場所 | メモ |
|---|---|---|
| 基本診断費 | `app.js` の `FEE` | 金額を変えるときは下の「金額を変えるとき」も必ず見る |
| はい／いいえの3問 | `app.js` の `QUESTIONS` | `title`・`lead`・`help`・`yes`・`no`・`summary`・`short` |
| 8つの症状ボタン | `app.js` の `SYMPTOMS` | `label`＝ボタンの文字　`sub`＝小さな説明 |
| 固定の文（「この画面を技術スタッフにお見せください」など） | `app.js` の描画部分（`html=` の行） | `phr([...])` の配列で書かれている |
| 画面の説明・手順 | `README.md` | 文面を変えたら README の該当箇所もそろえる |

## 2. 文面のルール（app.js 冒頭のコメントに従う）

- **句読点（、。）は使わない**　区切りは全角スペース「　」
- お客様に負担を突きつけず 店側から申し出る聞き方にする（例：「わからない場合は『はい』で大丈夫です」）
- 呼び方は「技術スタッフ」で統一（「担当者」「店員」は使わない）
- `title`・`lead` は **文節の配列** で書く　画面では配列の切れ目でだけ改行される
  - 例：`title:['残したい','写真や書類などの','データは','入っていますか？']`
- `help` は **行ごとの配列の配列**　`[['1行目の文節',…],['2行目の文節',…]]`
- 強調は `<strong class="warn">…</strong>`
- `summary` は集計・回答一覧・引き継ぎ画面に出る一文　`title` を変えたら `summary` もそろえる
- `short` は集計表とCSVの見出し　短く

## 3. 症状ボタンの注意

- ボタンは 2列×4行（8個）の配置で作ってある　**増減すると見た目が崩れやすい**　増やす・減らすときはユーザーに一度確認する
- `label` が **11文字以上** だと自動で小さい字（`long`）になる　なるべく10文字以内
- **キー名（`power`・`boot` など）は変えない**　過去の記録はキーで保存されていて 変えると集計で名前が出なくなる　文字だけ変えるときは `label` だけ直す
- `other` は必ず残す（選ばれなかったときの受け皿として使っている）

## 4. 質問を増やす・減らす・並べ替えるとき

文字を直すだけなら `app.js` だけで済む。質問そのものを増減するときは影響が広いので **先にユーザーに確認** してから：

- 流れは各質問の `next` でつながっている（最後の質問の `next` は `'symptom'`）
- 受付窓口への送信 `toRow()` は `data`・`pcpass`・`change` を名指しで送っている
- スプレッドシート側（`gas/Code.gs` と `gas/相談ナビ受付窓口_版3.gs`）も同じ列で受けている　→ 両方の列を合わせて直し「GASを貼り替えてデプロイし直す必要がある」とユーザーに伝える
- 画面右上の「約2分・全4問」と README の「全4問」も合わせる

## 5. 金額を変えるとき

`FEE` だけでなく次の3か所をそろえる：
1. `app.js` の `FEE`（表示用 例 `'2,200円'`）
2. `app.js` の `toRow()` の `fee:2200`（売上計算用の数字）
3. `gas/相談ナビ受付窓口_版3.gs` の `SHINDAN_FEE`（予備の値）→ GASの貼り替えが必要とユーザーに伝える
4. `README.md` の金額表記

## 6. 仕上げ

1. `sw.js` の `const CACHE = 'pcshindan-vN';` の N を1つ上げる
2. 構文チェック：`node --check pc-shindan-navi/app.js && node --check pc-shindan-navi/sw.js`
3. 句読点が紛れていないか確認：変更した行に「、」「。」がないか見る
4. 変更が分かるコミットメッセージで、指定ブランチにコミットして push（このリポジトリは日本語の短い1行メッセージ　例「症状ボタンの説明を短くする」）
5. ユーザーへの報告は日本語で：
   - 何をどう変えたか（変更前 → 変更後）
   - CACHE を何番に上げたか
   - GASの貼り替えが必要かどうか
   - iPadでは一度アプリを開き直すと新しい版になること
