# 再開のしかた・合言葉（USDJPY 自動分析）

SHO が次の作業を始めるときに言う言葉と、AI がそのとき最初にやることの対応表。
[[00_HOME/保管庫/AIへの頼み方カード|AIへの頼み方カード]] と同じ考え方で、この案件専用のもの。

## まず、再開の一言（どのパソコン・どのAIでも同じ）

```
ドル円自動分析の続き。Vault の 03_PROJECTS/USDJPY_Auto_Analysis/PROJECT_OVERVIEW.md と、docs の一番新しい作業ログを読んで、今の状況と次の一歩を報告して。
```

AI はこれを受けたら：①PROJECT_OVERVIEW を読む ②`docs/作業ログ_*.md` の一番新しいものを読む ③「現在の状態」「SHO 待ちのこと」「次の一歩」を 5 行以内で報告し、SHO の指示を待つ。勝手にコードを書き始めない。

### どこで言うか

| 場所 | できること | 注意 |
|---|---|---|
| claude.ai/code（クラウドの作業部屋） | 設計・コード作成・Vault への保存・画像の生成（CSV があれば） | TradingView・GMOコインに通信できない。データの更新は PC 側に頼む |
| SHO の PC の Claude Code（PowerShell で `claude`） | TradingView MCP でデータ更新、Python の実行、X 投稿（将来）、Vault の既存ノートの書き換え | 作業フォルダを Vault の `03_PROJECTS/USDJPY_Auto_Analysis` にして開くと、Vault のルールと記憶が効く |

## 別のパソコンで続きをやる手順（セーブポイント 2026-10-06）

Vault は Dropbox で同期されるので、別の PC でも同じフォルダが見える。コードもノートも Vault が正本。

1. Dropbox の同期が終わっているか確認する（`03_PROJECTS/USDJPY_Auto_Analysis/social/x_publisher.py` と `config/social.yaml` が見えれば最新）
2. PowerShell でそのフォルダに移動して `claude` を起動し、上の「再開の一言」を貼る
3. 動作確認（任意）：`python -m pytest tests -q` で 20 件合格 → `python run_4h.py --csv data/USDJPY_4H.csv --daily data/USDJPY_1D.csv --slot morning --now "2026-10-02 10:05"` で画像・解説・送信予定（`output/outbox/`）ができる
4. GitHub から取る場合（Vault が使えないときだけ）：`git clone` 後に `git checkout claude/nice-sagan-kgqry5`、フォルダは `usdjpy-auto-analysis/`

## 作業ごとの合言葉

| SHO が言う言葉 | AI がやること |
|---|---|
| **ドル円4時間足を解析して** | `data/USDJPY_4H.csv`・`USDJPY_1D.csv` を読み、`run_4h.py` を実行し、画像と解説を見せる（引き継ぎメモの「第一段階の完成条件」）。X には投稿しない |
| **データを最新にして** | PC 側：TradingView MCP で CSV を書き出す（手順は PROJECT_OVERVIEW の「SHO の手順」）。クラウド側：PC で書き出すよう案内する |
| **線の感想：〇〇** | 感想を `docs/ANALYSIS_RULES.md` の「確認したいこと」と照らし、`config/analysis.yaml` を直して作り直し、前後の画像を並べて見せる。ルールが変わったら ANALYSIS_RULES の更新履歴に 1 行足す |
| **X投稿の準備を始めて** | `docs/X自動投稿の進め方.md` のとおり、`social/x_publisher.py`・`config/social.yaml`・定時実行バッチを DRY RUN で作る。先に「カギはあるか」「1日何回か」を確認する |
| **本番投稿をONにして** | SHO の明示の了承を確認してから `config/social.yaml` の `dry_run` を false にする。それまでは絶対に投稿しない |
| **1時間足に広げて** | 線のルールが確定していることを確認してから、4時間足の方向を参照する形で 1時間足を作る（STEP 4） |
| **セーブして**／**セーブポイントを作って** | ①Vault に最新ファイル ②GitHub にコミット＋push ③その日の作業ログを `docs/` に 1 本 ④このノートの「セーブポイントの中身」と PROJECT_OVERVIEW の「最新のセーブポイント」を更新。終わったら保存場所と再開手順を報告 |
| **状況を教えて** | PROJECT_OVERVIEW と最新の作業ログを読んで、現在地と SHO 待ちを 5 行以内で報告 |

## もっと短い合言葉を使いたいとき（任意）

「ドル円の続き」の一言で済ませたい場合は、PC 側の Claude Code に次を貼って、Vault の共通ルールに 1 行足してもらう：

```
AGENTS.md の末尾に、次の見出しと本文を足して。既存の行は変えないで。
## USDJPY自動分析
- ユーザーが「ドル円の続き」「ドル円自動分析の続き」「ドル円4時間足を解析して」と言ったら、まず 03_PROJECTS/USDJPY_Auto_Analysis/PROJECT_OVERVIEW.md と docs/再開のしかた_合言葉.md を読み、その対応表に従う。
```
