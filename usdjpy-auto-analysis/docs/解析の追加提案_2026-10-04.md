# 解析の追加提案（2026-10-04・4視点の案出し → 査読 → 統合）

## 1. 今のシステムの強みと、足りないもの
- 強み：サポレジ・平行チャネル・EMA3本・相場環境の点数化が「数値で決めて言葉にする」形で動いており、根拠を書く土台ができています。
- 足りないもの①：SHO の三本柱（フィボ・SQZMOM・RSI ダイバージェンス）がまだ無い。
- 足りないもの②：「強い上昇」と「安値切り下げ」が同時に出るなど、判定同士の矛盾を自分で検出できない。
- 足りないもの③：「どの足が確定済みか」「前日はどの足か」の決め方がモジュールごとにばらばら（前日終値が1日古い例を確認）。
- 足りないもの④：1H・5M への展開と、言ったことの答え合わせの仕組み。

## 2. 提案（3段階）

### A. すぐ入れる（SHO の希望に直結・4H だけで動く）

**A1 確定足と判定幅の一元管理（土台）**
【何を】「足の終了時刻 ≤ 実行時刻」で最後の確定足を決める共通関数と、接触幅（ATR×0.4）・終値基準などを config の1か所にまとめる。【なぜ】15分遅延・夏冬時間・週末で「前日」「確定足」がずれると、以降の全判定が食い違う。【判定】日足は NY クローズ区切り、4H は夏 10:00/22:00・冬 11:00/23:00 確定。【言い回し】「判定は 10/03 18:00 までの確定足に基づきます」。【決めること】日の区切り（NY クローズか JST か）。

**A2 ダウ理論の構造判定＋矛盾の「ただし書き」**
【何を】最高値の直前の安値（押し安値）を「構造が崩れる価格」として1本の点線で示し、6区分（高値更新中／更新待ち／崩れた…）で状態を返す。ラベルと根拠がねじれたら自動で「ただし〜」を添え、矢印を一段弱める。【なぜ】ダウ理論では押し安値を終値で割るかどうかが唯一の転換条件。実データでは 159.037 の直前安値 156.822 を終値で割った足はゼロ＝「構造は保たれているが高値更新待ち」が正しい読み。【判定】崩れ＝終値 < 押し安値 − ATR×0.1。主要スイングは振幅 ATR×2 以上で選別。【言い回し】「上昇の構造は終値ベースで保たれていますが高値更新ができておらず調整中。156.822 を終値で割ると構造が崩れます」。【決めること】終値かヒゲか、相場環境の項目4と差し替えるか。

**A3 前日・前週の高安・終値、当日・当週始値**
【何を】日足から機械的に決まる水準を灰色破線で出し、サポレジと重なれば線を増やさず重要度に加点。【なぜ】反応回数ゼロでも「誰もが見ている水準」で、スイング由来のサポレジと重なる所は根拠が二重になる。【判定】前日＝確定済みの最後の日足、前週＝金曜クローズ区切り、重なり ATR×0.4。【言い回し】「現在値は前日高値 158.220 と前日安値 156.951 の間、前週高値 158.457 の下」。【決めること】出す種類（高安だけか終値・始値も）、日本語ラベルか略号か。

**A4 ATR による値幅の文脈**
【何を】4H ATR を pips と過去100本の分位で、日足 ATR14 を「1日の値幅目安」として示し、注目帯までの距離を ATR 倍で4段階（目前／数本以内／数日の射程／中期）、当日の消化率も添える。【なぜ】同じ 8 pips でも ATR 50 の日と 120 の日では意味が違う。ボラティリティは持続しやすく再現性が高い。【判定】消化率 <40% 余地あり、>80% 出し切りに近い。【言い回し】「157.957 は目前（8pips）。159.037 は数日の射程（116pips、ATR 2.2倍）」。【決めること】しきい値、想定レンジ帯を 1H・5M 画像に描くか。

**A5 フィボナッチ・リトレースメント（＋エクステンション）**
【何を】直近の推進波（起点 L→高値 H）に 38.2／50／61.8% を描き（23.6／78.6 は文章のみ）、サポレジ・EMA・チャネル中央線との重なりを根拠に書く。高値更新後は N 計算値（100%）と 161.8% を目標として文章に添える。【なぜ】押し目は 38.2〜61.8% で止まりやすく、重なった所が本命。実データで 38.2%＝156.688 がサポート帯、61.8%＝155.237 がサポート 155.259 とほぼ一致し、09/30 安値は 43% 押しで反発。【判定】波は確定ピボット・大きさ ATR×3 以上、起点はチャネル基準線と同じ点、78.6% より深い押しは「この波の押し目としては深すぎる」。【言い回し】「09/30 の安値 156.375 は 38.2〜50% の押し目帯で反発しており、サポート帯とも重なります」。【決めること】日足の波も出すか、比率、線の色。

**A6 スクイーズモメンタム（SQZMOM）**
【何を】LazyBear と同じ計算で、スクイーズ ON/OFF・継続本数・モメンタムの4色と強さを出し、相場環境の直後に1段落。【なぜ】値動きの圧縮＝エネルギーの蓄積で、解放後に大きめの動きが出やすい。「いつ動くか」を示し「どちらへ」は示さない指標、と役割を分けて書く。【判定】BB 倍率は TradingView 表示と合わせて KC の 1.5 を既定（2.0 だと判定が逆転）。継続本数は過去300本の分位で長短を言う。【言い回し】「17本連続でスクイーズ中（過去の中央値より長め）。モメンタムはプラスながら3本連続で縮小」。【決めること】1.5 の癖に合わせるか、サブパネルに描くか。

**A7 RSI ダイバージェンス**
【何を】確定スイング2組の価格と RSI の高低が食い違えば検出し、両方の RSI 値を併記。【なぜ】高値更新なのに RSI が更新できない＝勢い低下の兆し。実データで 158.058（RSI 75.5）→159.037（72.4）の弱気ダイバージェンスが成立。【判定】価格差 ≥ ATR×0.3、RSI 差 ≥ 3、有効期限 pivot_right＋15本。「反転」ではなく「勢い低下」と書き、A2 の構造崩れと合わさって初めて転換の根拠にする。【言い回し】「価格は高値を更新した一方 RSI は切り下がっており、159 円台で上値が重くなった背景と見られます」。【決めること】隠れダイバージェンスも載せるか、画像の印。

**A8 根拠の重なりゾーン・帯描画・シナリオ表**
【何を】サポレジ・フィボ・EMA・チャネル・前日高安・押し安値・節目を1つの表に集め ATR×0.4 で束ね、重みの合計で格付け。上下2つずつを「注目価格帯」とし、帯＋主線1本で描き、反応点に●と★ランク。上下シナリオは「発動条件／行き先／崩れる条件」の表に。【なぜ】線を増やさず根拠を増やせる唯一の構造。無効化条件を先に言うことが後出しを防ぐ。【判定】種類が2つ未満は単独線扱い、得点＝重み合計 − 距離×係数。【言い回し】「157.95〜158.06：レジスタンス（15回反応）＋前日高値＋フィボ 23.6%」「メイン（根拠5）：157.957 を終値で上抜け → 159.037。崩れる条件：156.822 割れ」。【決めること】各根拠の重み、●の上限数。

**A9 表現の安全弁**
【何を】禁止語（必ず・絶対・推奨・エントリー・〜べき）を投稿直前に機械チェックし、免責と「価格は参考値・15分以上の遅延・判定は確定足の終値」を自動付与。【なぜ】1回の失言で信頼が崩れる媒体。【判定】「買われすぎ」「売り優勢」は許可リストで守る。【決めること】禁止語リスト、ヒット時に止めるか言い換えるか。

### B. 次に入れる（4H の読みを深める）
- **ブレイク・ダマシ・リテストの6区分**：線に対して「何が起きたか」を言語化。4H は終値2本連続で確定、ダマシ回数も返す。例「158.457・158.220 と上ヒゲで抜けて終値で戻る形が2回続いています」。決めること：「ダマシ」という言葉を使うか。
- **ADX/DMI＋勢いスコア**：方向（EMA・構造）と勢い（SQZMOM・RSI・DMI）の2軸で「上昇基調の一服」などの定型文に。実データは方向 +3 に対し勢い −2。決めること：定型文の言葉。
- **EMA 乖離（ATR 単位）**：過去300本の分位で「追随より反動に注意」。
- **レンジ専用処理**：ボックスの上限・下限・継続本数、三角の収れん線（頂点到達前に抜けなければ形は失効）。
- **線に触れた足のローソク足パターン**（上ヒゲの長い足・包み足・インサイド・NR7、日足も同じ関数）。
- **フィボ・チャネル**（既存チャネル内の 38.2／61.8 の斜め線、接触2回以上のみ描く）。
- **長期レベル**（160 円など当局の警戒感が意識される水準・史上高値・年初来高安。現在値から日足 ATR×2 以内のときだけ）。

## 3. 3枚組の役割分担
| 足 | 役割 | 言うこと | 線 |
|---|---|---|---|
| 4H | 環境と待ち受ける帯 | 方向・構造・SQZMOM・注目帯2つ・シナリオ表 | 自身の線（主） |
| 1H | 壁へ向かう過程 | 直近の波→向かっている壁→1H の環境→4H との整合（4行） | 4H の線を細い破線で継承、自身は各2本 |
| 5M | 壁での反応 | 今の位置→反応4分類（接近中／到達・反発／到達・抜け／離れている）→次の確認点（3行） | 一番近い上位帯1〜2本＋EMA20/50＋当日高安 |
下位足は上位足の判定を覆さず、数字は再計算せず継承します。

## 4. 投稿の型
- **10:05 朝のプラン**：①前日の総括（日足終値 vs EMA50・前日足の形）②本日のイベント ③想定レンジ ④4H の環境・構造・注目帯2つ ⑤メイン／サブシナリオ ⑥確定足の時刻と免責。
- **20:05 中間報告**：①10:05 からの変化点（ラベル・線の移動・ブレイク・役割転換）②東京時間の高安と朝の線の反応 ③日足の途中経過と消化率 ④今夜のイベント ⑤NY 時間に見る線2つ ⑥確定足の時刻。変化が無い日は1行だけ、または見送り。
- 文字数は文単位で切り詰め、画像は1ツイート1枚・ALT テキスト必須。

## 5. 答え合わせの仕組み
投稿ごとに注目帯・シナリオの発動条件と行き先・崩れる条件・相場環境ラベルを台帳（追記専用 CSV）に残し、次回実行時に確定足6本（週末は自動でまたぐ）で採点します。ゾーンは「到達→反発／上抜け」、シナリオは「発動→的中／不発」、方向は符号の一致。主指標は「到達後に反発した割合」。20件に満たない間は「集計中（n件）」と書いて率を出しません。解説末尾に「前回 10/03 20:05 注目の 157.957 → 到達・反発（高値 158.029）」のように1〜2行、金曜に週次まとめ。採点ルールは固定文で添えます。

## 付録：査読者が指摘した「見落とし」（原文）

- 確定足・データ鮮度・休場の横断ルール（所有者が無い）：「最終足の終了時刻 ≤ 実行時刻」で確定足を決める共通関数、GMO の遅延に対する再取得（回数・間隔を config）、土日・元日・休場日のスキップ、前回と同じ最終足なら投稿しない二重投稿防止。日足の iloc[-2] 問題（金曜クローズ後は iloc[-1] が前日）も同じ関数で解決する。提案 7・13・22・24・33 がそれぞれ触れているが 1 か所にまとめる必要がある。
- データ元の統一と価格差の注記：定時実行は GMO（BID）、SHO が見る TradingView は OANDA の中値で、線の価格が数 pips ずれる。答え合わせ（34）や「157.957 に反応」の検証が食い違う原因になるので、priceType（BID／ASK／MID の合成）を config で選び、GMO と CSV の終値差を定期的に計測してログに残し、投稿の注記に「参考値」と書く。
- 判定基準の統一表：終値ベースかヒゲベースか、接触幅の ATR 倍率（0.3／0.4／0.6／0.15 が提案ごとにばらばら）、確定足の定義を config の 1 セクション（tolerances）に集約し、全モジュールが同じ値を参照する。ばらばらのままだと「ダマシ」「反応」「合流」の判定が線ごとに食い違う。
- 解説の情報量の上限（優先順位と文字数予算）：提案を全部入れると長文が 3 倍になり読まれない。根拠は重み順に上位 N 件だけ本文に出し、残りは JSON と md の付録に回す。section ごとの文字数予算を social.yaml に持ち、X 用は固定枠にする。
- 回帰テスト基盤（ゴールデンテスト）：本物の CSV スナップショット（data/ の 4H 1000 本・日足 400 本）に対する各モジュールの出力（サポレジ・チャネル・構造・SQZMOM・RSI など）を期待値として固定し、提案を 1 つ足すたびに既存の結果が変わっていないことを自動で確認する。Pine 版を作るときの突き合わせにも使う。
- スイング確定ラグの扱い：右 5 本のピボットは 4H で 20 時間遅れて確定するため、構造判定（4）・ダイバージェンス（14）・波の比較（11）はすべて遅れる。「確定済みの高安は mm/dd hh:mm まで」を解説に明記するか、速報用に右 2 本の「暫定スイング」を別枠で持つかを SHO が決める。
- 週足の方向（日足から合成した週足の EMA20 など）：大局を日足 EMA50 だけで見ているので、週足レベルの方向を 1 行足すと提案 24・32 の長期レベルと整合する。日足 CSV を W-FRI でリサンプルするだけで追加データ不要（工数 small）。
- 確定足と時刻の一元管理（全提案の土台）：どの時間足でも「足の終了時刻 ≤ 実行時刻」で最後の確定足を決める共通関数が無い。実際に食い違いを確認した：日足 CSV の最終行（10/02 セッション）は 4H 6 本分がそろった確定足なのに、既存 pipeline の _higher_timeframe は iloc[-2] を使うため「前日終値 158.088」と 1 日古い値を出し、提案 5 と 24 も「前日高安」の値が食い違っている。夏冬時間（4H の確定時刻が 10:00／22:00 と 11:00／23:00 で変わる）、15 分遅延、週末・祝日の欠損もここで吸収する。第 0 段階の最初に入れるべき。
- 主要スイングと小スイングの階層（ZigZag の振幅フィルタ）：左右 5 本のピボットは小さな波も拾うため、「直近 2 組の高安」判定が「拡大」のような矛盾を生んでいる。波の振幅（例 ATR×2 以上、config）で主要スイングを選別して major／minor のタグを付け、ダウ理論（4）・フィボ（1）・チャネル・レンジ検出（8）・ダイバージェンス（14）がすべて同じ主要スイングを参照するようにする。これが無いとモジュールごとに違う波を語り、3 枚組でも数字がずれる。
- 日足・週足スイングのサポレジ（levels.py を日足に適用）：提案 24 の前日高安はカレンダー由来で、ANALYSIS_RULES 項目 3「週足・日足の主要サポレジ」（数か月単位の反応帯、例 160.299 のような水準）は依然として未実装。既存 build_levels を df_daily（ピボット左右 5 本 ≒ 1 週間）に流すだけで出せる。提案 12 のゾーン候補に重み 1.5 で入れる。
- 線の過去成績（バックテストによる反応の質）：今の根拠は「反応 15 回」という回数だけ。各帯について過去の到達後に「反発した／終値で抜けた」の内訳を集計すれば「過去 15 回の到達のうち 11 回で反発」という桁違いに強い根拠になる（提案 34 の採点ロジックを過去に向けて適用するだけ）。あわせて ATR×0.3・0.6・1.5 倍などの手置きしきい値を 1000 本の履歴で校正する検証ハーネスを作り、過剰適合を防ぐ。
- 描画予算（画像の情報量の上限ルール）：提案の多くが線を増やす。水平線 6 本以内・斜線 4 本以内・サブパネル 2 枚以内のような総枠と、レイヤーの優先順位（コンフルエンスゾーン ＞ 押し安値 ＞ 前日高安 ＞ フィボ単独線）、枠を超えたら「文章のみ」に落とすルールを 1 か所で決める。提案 12・36 だけでは足りない。
- Pine 移植可否の明記：SHO は Pine Script 版を望んでいるが、サポレジのクラスタ化やチャネル候補の選択は Pine で再現しにくく、フィボ・SQZMOM・RSI・ADX・ATR・前日高安は容易。各提案に「Pine 移植：容易／困難」の列を付け、config の項目名を Pine の input 名と揃えておくと後の移植が楽になる。
- 価格源の差の扱い：TradingView（OANDA）と GMO（BID）では高安が数 pips ずれ、前日高安や反応回数が変わる。データ源を切り替える日を台帳（34）に記録し、データ注記（43）に価格源を明記する。GMO の日足の区切り（JST 6:00／冬 7:00）も切替時に一度検証する。
- インターマーケット（米 10 年債利回り・DXY・日経）はテクニカル分析の正当な領域だがデータ源が無いので今は保留。将来 TradingView MCP から取れるなら「方向の裏付け」1 行として検討する。
- 全体の実装順（査読者案）：第 0 段階＝確定足管理・38 矛盾検出・43 安全弁・4 ダウ理論構造・24 前日高安（5・29 統合）・16 ATR 文脈（25・42 統合）。第 1 段階＝1 フィボ・13 SQZMOM・14 RSI ダイバージェンス・12 コンフルエンス（37 統合）・36 帯描画・35 シナリオ表。第 2 段階＝6 ブレイク判定（23 統合）・15 ADX・21 勢いスコア・20 EMA 乖離・2 エクステンション・3 フィボチャネル・8 レンジ・9 ローソク足（30 統合）・32 長期レベル。第 3 段階（1H・5M データが前提）＝7 MTF（22・39 統合）・26 セッション（10・31 統合）・28 イベント・33 スロット（41 統合）・34 答え合わせ・40 投稿型・27 仲値。却下＝17 ティック出来高・18 MACD・19 BBW。
